# NativeLingo 开发规范

桌面界面的视觉语言、交互状态、文案、可访问性和前端发布门槛统一定义在
[前端设计与实现规范](FRONTEND_DESIGN.md)。任何前端改动都应同时遵守本文的数据契约与该
设计规范。

## 模型输入必须单一来源

凡是阈值敏感的本地模型，生产、自动化测试、离线基准和发布验收必须使用同一份生产
预处理代码。禁止在测试脚本中用“参数看起来相同”的 Canvas、Pillow、OpenCV 或其他
实现模拟生产输入，并据此宣称端到端验收通过。不同解码器、缩放核、色度抽样和编码器
即使尺寸与质量参数相同，也可能产生足以跨越阈值的像素差异。

看图识物的唯一模型输入契约位于
`desktop/backend/core/memorize_image.py::canonicalize_upload`：

1. 接收客户端上传的原始字节；
2. 应用 EXIF orientation；
3. 使用 LANCZOS 将长边限制为 1920px；
4. 固定编码为 quality 90、4:2:0、非 progressive JPEG；
5. 从该 JPEG 重新解码模型图片，保证检测像素与服务器保存、后续裁剪像素一致。

前端对 JPEG/PNG/WebP 必须上传原文件，不能提前缩放或重编码。浏览器 Canvas 只允许
作为后端不能解码格式（例如 HEIC）或超过上传上限文件的传输适配器；适配后的文件仍须
经过后端同一 canonicalizer。检测坐标以 API 返回的 `image_size` 为唯一尺寸依据。

## 测试与发布验收

- 单元测试直接调用生产 canonicalizer，覆盖 EXIF、缩放、固定编码、重复运行确定性和
  无效输入。
- API 测试上传原始图片字节，并断言检测使用 canonicalizer 返回的图片；不得先在测试
  中自行生成所谓“App 等价 JPEG”。
- `scripts/photo_gallery_baseline.py` 与 `scripts/photo_gate.py` 必须复用生产
  canonicalizer。检测框预览按基准记录的 canonical `size` 映射回原图。
- 私人验收图片不得提交仓库。发布验收时，应把原文件直接上传给实际挂载 DMG 内的后端，
  并记录 HTTP 状态、耗时、关键标签、分数和框；不得上传离线预处理后的替代文件。
- 任何模型预处理改动都必须重新执行相关单测、60 图基准、预览复核、App/DMG 构建和
  挂载后原图上传验收。只验证构建目录不算安装包验收。

## 识别发布门槛

- 小图全图 pass：p95 ≤200ms。
- 触发全局切片的大图：p95 ≤8s，单图最大值 <12s。
- 零检测图片数量不得上升，原有关键标签不得消失，不得增加明显重复框。
- 达不到门槛时停止发布并报告结果；不得擅自降低逐标签阈值、改回其他扫描策略或使用
  不同预处理输入规避失败。
