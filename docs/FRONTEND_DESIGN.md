# NativeLingo 前端设计与实现规范

本文档是 NativeLingo 桌面前端的设计基线，也是后续界面修改的评审依据。它描述当前
`main` 分支编辑式学习工作台的视觉语言、交互规则、工程边界和验收方式。界面实现与本文
冲突时，应先更新设计决策并说明原因，不应在局部组件中自行发明另一套规则。

## 1. 产品体验目标

NativeLingo 不是游戏化打卡产品，也不是营销落地页。它是一件面向桌面场景的本地英语
学习工具，核心体验应接近编辑器、媒体工作台和轻量专业软件：

- 用户一眼知道当前可以做什么，不需要阅读操作教程。
- 控件本身表达功能，文字只保留关键任务、学习内容和可执行反馈。
- 视觉有明确作者感，但不以装饰抢夺学习内容的注意力。
- 状态变化发生在原位置，用户不需要在页面中寻找新出现的提示卡。
- 本地处理、模型准备和失败恢复清晰可见，但不长期占用主内容区域。

设计的核心判断标准是：删掉一段说明后，如果图形、位置、状态和反馈仍能让用户正确完成
任务，就应删掉这段说明。

## 2. 设计方向与来源

本轮重构采用确定性设计取样：

```text
seed=163
layout=Editorial Split
typography=Geist
components=Horizontal Accordions, Feedback Carousel, Infinite Marquee
motion=Image Scale & Fade, Card Stacking
```

这些方向在桌面工具中的实际映射为：

| 设计方向 | NativeLingo 中的实现 |
| --- | --- |
| Editorial Split | 跟读的 4+8 来源栏与任务画布，识物的 5+7 任务提示与上传画布 |
| Horizontal Accordions | 视频和音频模式选择器，激活项显示短标签，非激活项只显示图形 |
| Feedback Carousel | 每句只展示一个问题词反馈，通过前后按钮浏览 |
| Infinite Marquee | 识别词汇确实溢出时才循环，悬停、聚焦和减少动态时暂停 |
| Image Scale & Fade | 照片和识别框进入时进行轻微聚焦，不改变布局尺寸 |
| Card Stacking | 逐句结果随滚动形成编辑式叠层，不生成卡片墙 |

AIDA 在应用内被转换为任务顺序，而非营销结构：顶部导航建立位置感，主画布承接任务，
选择与探索形成操作，分析反馈解释结果，当前关键动作始终留在上下文附近。

## 3. 明确禁止的界面模式

以下模式会让界面重新产生模板感或明显的 AI 生成痕迹，不得引入：

- 功能区使用 emoji 或吉祥物代替功能图标。
- 使用中点、竖线或连续元标签表达并列关系。
- “中文标题 + English Title”式双语重复标题。
- “小标题 + 解释正文”重复堆叠功能说明。
- 用编号卡片表现素材、选句、录音、分析等线性步骤。
- 为每段内容增加独立白卡、粗边框、彩色软底或三维按钮。
- 用渐变、玻璃高光、数据徽章或 Bento 墙制造所谓高级感。
- 在按钮旁重复解释按钮已经表达的动作。
- 成功后显示冗长确认文案；成功状态应直接变成可继续操作的界面。

例外只包括原位错误恢复、首次空状态和确实无法由图形表达的高风险动作。

## 4. 品牌与视觉令牌

### 4.1 品牌资产

现有猫形资产继续保留，但使用范围固定：

- 应用图标。
- 顶部品牌锚点。
- 极少量真正没有内容的品牌空状态。

猫形资产不得出现在录音、上传、播放、主题、状态或导航等功能按钮中。宽度足够时顶部显示
`NativeLingo` 字标；窄屏只保留猫形锚点。

### 4.2 字体

- 英文、数字和品牌字样使用随应用打包的 Geist Variable。
- 中文依次回退至 PingFang SC、Hiragino Sans GB 和 Microsoft YaHei。
- 不从网络加载字体，离线运行时视觉必须完全一致。
- 主任务标题最多两行，避免出现窄而长的六行标题。
- 正文不依赖全大写、过度字距或超轻字重制造层级。

### 4.3 颜色

浅色主题是默认主题：

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| Canvas | `#F2F0EA` | `#12130F` | 应用画布 |
| Surface | `#FAF9F5` | `#191B16` | 主要工作表面 |
| Ink | `#171814` | `#F3F2EA` | 主文字和关键控件 |
| Muted | `#6B6F65` | `#A4A89C` | 次级反馈 |
| Line | `#D8D8CF` | `#30342B` | 细分隔线 |
| Accent | `#B7F34A` | `#C7F85A` | 选区、状态和品牌点睛 |

红色仅用于录音、错误和必须立即注意的风险；琥珀色仅用于准备中和警告。品牌绿色不能作为
所有按钮的默认填充色。

### 4.4 表面、圆角与阴影

- 主要圆角分为 8、14、22px，不增加新的相近规格。
- 主要布局依赖留白和 1px 分隔线，不依赖统一白卡。
- 阴影只用于浮动工具栏、原位操作坞和滚动叠层，保持低对比度。
- 背景使用本地 SVG 极轻纸张颗粒，不能影响文字对比度。

## 5. 应用框架

### 5.1 顶部工具栏

顶部工具栏目标高度为 56px，结构固定：

1. 左侧为品牌锚点。
2. 中部为“跟读”和“识物”两个模块入口。
3. 右侧为本地后端状态点、主题切换和信息入口。

后端状态使用点的颜色表达。点击状态点或信息按钮后才展开详情；模型名称、格式支持、隐私
信息和冷启动说明不进入主任务布局。

### 5.2 图标

功能图标统一来自 `desktop/src/modules/icons.js` 的定制 SVG 符号。图标遵循 24px
viewBox、圆角端点和一致线宽。所有纯图标按钮必须同时具有：

- 可访问名称。
- 键盘可见焦点。
- 仅在需要时出现的 tooltip。
- 至少 44×44px 的可点击目标。

“开始分析”“换张照片”“重试”等关键动作保留短文本，标签原则上不超过六个汉字。

## 6. 布局与响应式规则

基准窗口为 760×900，布局使用 12 列概念网格：

- 跟读默认是 4+8：来源栏 4 列，媒体与字幕画布 8 列。
- 识物初始页是 5+7：任务提示 5 列，上传画布 7 列。
- 不保留没有内容的 Bento 单元，不为了对称增加占位卡。

响应式断点与行为：

| 宽度 | 行为 |
| --- | --- |
| 801px 及以上 | 显示完整品牌字标和双列工作台 |
| 680–800px | 保留品牌字标和双列工作台，收紧边距和来源栏 |
| 679px 及以下 | 工作台纵向排列，模块标签收起为图标，主要操作仍保持 44px |

必须在 600×720、760×900 和 1024×900 下保证无横向滚动。页面增高时允许纵向滚动，
但当前关键动作不能被固定高度容器裁掉。

## 7. 状态与反馈原则

### 7.1 原位反馈

准备麦克风、倒计时、录音、整理录音和分析都在同一操作坞变化。禁止为了状态更新新增提示卡
或推动页面布局。用户操作后 100ms 内必须出现以下至少一种反馈：

- 按钮状态或图标变化。
- 原位状态文字变化。
- 画布骨架或遮罩出现。
- 选区、焦点或结果轨道变化。

### 7.2 状态机

跟读状态由 `speakingStage` 表达：

```text
idle -> source-ready -> range-started -> range-ready
     -> preparing -> recording -> recorded -> analyzing -> results
     -> error
```

识物状态由 `memoStage` 表达：

```text
upload -> analyzing -> photo -> detail
       -> practicing | scenario
       -> error
```

状态同时写入轻量状态容器和根元素数据属性，便于测试与后续样式扩展。异步识别、物品详情、
情景生成和发音评分必须使用请求令牌；旧请求完成后不得覆盖新任务。

### 7.3 错误与恢复

错误文字只包含原因和下一步。例如：“识别失败：模型尚未准备好。请重试或换张照片。”
错误必须出现在原任务区域，并提供仍然可见的重试、换图或返回动作。不得让超时请求继续显示
无限加载状态。

识物普通请求保持 15 秒上限，发音评分保持 18 秒上限；前端超时不能超过既有后端契约。

## 8. 跟读工作流

### 8.1 素材选择

视频和音频使用横向展开的模式选择器。视频来源栏只显示素材本身和必要文件信息；首次转写
说明进入信息浮层。音频上传是一个明确的大目标区域，不另外显示步骤编号。

### 8.2 句子范围

范围继续使用两次点击：第一次确定起点，第二次确定终点。状态通过以下方式表达：

- 起点和终点使用品牌强调色。
- 中间句子使用低强度选区带。
- 顶部只显示当前范围结果，不重复教程。
- 第三次点击开始新的选区。

### 8.3 录音与分析

中央录音控件、等宽计时器、视频重放和“开始分析”组成单一操作坞。录制过程中只改变图标、
颜色、波形感和状态，不新增布局块。参考视频与录音播放器继续保留现有精确回放行为。

### 8.4 结果

结果结构固定为：

1. 一个大综合分。
2. 准确度和流畅度两条轨道。
3. 逐句堆叠。
4. 单一问题词反馈浏览器。
5. 下一次练习重点和韵律摘要。

原声、我的录音和词级 A/B 回放使用图标按钮，并附着在对应句子或词旁。颜色只表示反馈
等级，不能替代文本或可访问名称。

## 9. 识物工作流

### 9.1 初始与上传

初始页左侧只保留一句任务提示和本机运行标识，右侧为大幅上传画布。上传区域必须支持：

- 文件选择。
- 拖放。
- 键盘操作。
- 可见焦点。

格式、隐私和模型信息放入信息入口。图片提交后，原图成为主要画布，骨架和扫描状态直接覆盖
照片区域。

### 9.2 识别框与词汇带

识别框使用细线轮廓。标签默认弱化，只在悬停、聚焦或选中时完整显现。所有识别框必须支持
键盘 Enter 和 Space。

物品词汇进入照片下方的横向词汇带。只有 `scrollWidth` 确实超过容器宽度时才复制内容并
启动循环；悬停、键盘聚焦和减少动态模式立即停止。

### 9.3 物品检查器

详情不再顺序堆叠内容物、部件、发音和情景。单一检查器提供三个互斥模式：

- 探索：显示整件物品、部件、内容物和图中位置。
- 跟读：聚合标准发音、录音、计时和评分。
- 情景：显示一条短对话浏览器，英语属于学习内容，中文只作完整句翻译。

返回整图时释放当前评分音频和局部状态；离开识物模块时继续调用模型释放接口。

## 10. 动效规范

动效只承担位置关系、进入层级和状态确认，不承担装饰。实现集中在
`desktop/src/modules/motion.js`，只加载 GSAP core、Flip 和 ScrollTrigger。

| 场景 | 时长 | 属性 |
| --- | --- | --- |
| 模块和模式切换 | 240–320ms | transform、opacity |
| 照片进入 | 500–700ms | scale、opacity |
| 识别框进入 | 约 280ms，短 stagger | scale、opacity |
| 结果堆叠 | 随滚动渐进 | transform、opacity |

禁止通过动画修改宽度、高度、边距或其他引发布局抖动的属性。所有动效通过
`gsap.matchMedia()` 响应减少动态设置；CSS 中的录音、扫描、骨架和词汇带动画也必须在
减少动态模式中停止或近似瞬时完成。

## 11. 文案规则

界面控制文案只使用中文；英语只用于品牌、素材文件名和学习内容。文案集中规则由
`desktop/src/modules/copy.js` 和测试共同约束。

- 不使用 emoji。
- 不使用中点或竖线表现并列。
- 不使用编号步骤标题。
- 不重复显示中英文同义标题。
- 不把格式、隐私、模型等元信息长期放在主任务区。
- 状态文案描述正在发生的事情，不描述系统内部实现。
- 错误文案必须包含一个明确的恢复方向。

## 12. 可访问性

最低要求：

- 正文、控件、焦点与状态颜色达到 WCAG AA。
- 常规操作目标至少 44×44px。
- 所有图标按钮具有 `aria-label`。
- 所有实时状态使用适当的 live region。
- 所有鼠标操作都具有键盘路径。
- 焦点顺序遵循视觉顺序，不使用正数 `tabindex`。
- 减少动态模式关闭非必要动画。
- 不仅依赖颜色区分正确、警告和错误。

页面保留“跳到主要内容”入口；视觉回归中单独保存键盘焦点和减少动态状态。

## 13. 工程结构与边界

前端保持原生 JavaScript，不迁移 React。Vite 负责开发和构建，资源基址保持 `./` 以兼容
Tauri 自定义协议。

| 文件 | 职责 |
| --- | --- |
| `desktop/src/index.html` | 稳定语义结构和可访问关系 |
| `desktop/src/styles.css` | 令牌、布局、组件外观和响应式规则 |
| `desktop/src/main.js` | 业务流程编排和现有 DOM 接口连接 |
| `desktop/src/modules/shell.js` | 顶部框架、主题、信息面板和检查器切换 |
| `desktop/src/modules/state.js` | 轻量应用状态容器 |
| `desktop/src/modules/runtime.js` | 后端地址、鉴权、超时、错误归一化和日志 |
| `desktop/src/modules/speaking.js` | 跟读状态和句子范围规则 |
| `desktop/src/modules/memorizing.js` | 识物状态、预处理契约和词汇聚合 |
| `desktop/src/modules/recording.js` | MediaRecorder、计时器和录音状态 |
| `desktop/src/modules/results.js` | 分数、语速和反馈浏览规则 |
| `desktop/src/modules/motion.js` | GSAP 动效与减少动态适配 |
| `desktop/src/modules/icons.js` | 唯一功能 SVG 图标来源 |
| `desktop/src/modules/copy.js` | 集中式功能文案和反模式规则 |

新增功能优先进入对应模块，不得继续在 `main.js` 中复制鉴权、超时、录音或评分格式逻辑。
动态学习内容必须使用 DOM 节点和 `textContent`，不得把后端返回值直接拼入 `innerHTML`。

## 14. 后端兼容性约束

前端重构不能改变以下接口：

- 后端路由与请求负载。
- `Authorization` 鉴权头。
- 视频和音频流的 token 查询参数。
- `window.__NATIVELINGO_BACKEND__`。
- `window.__NATIVELINGO_TOKEN__`。
- 图片预处理契约 `memorize-image-v1`。

照片预处理的单一来源仍是后端 `canonicalize_upload`。前端只在后端不能解码或文件超过
上限时使用 Canvas 作为传输适配器，不能把浏览器预处理当作模型输入规范。

## 15. 测试与验收

提交前至少执行：

```bash
cd desktop
npm run build
npm test
npm run test:e2e

cd src-tauri
cargo check

cd ../backend
GGML_METAL_NO_RESIDENCY=1 ../../.venv/bin/pytest -q
```

Tauri 发布前还应执行：

```bash
cd desktop
npx tauri build --bundles app --no-sign
```

Vitest 覆盖状态容器、鉴权、超时、错误归一化、录音状态、选择范围、反馈浏览和文案规则。
Playwright 覆盖视频跟读、音频上传、录音分析、结果浏览、照片识别、物品详情、发音评分、
情景生成、零识别、过期请求、模型进入和释放，并保存以下视觉基线：

- 600×720 浅色跟读。
- 760×900 浅色跟读。
- 1024×900 浅色跟读。
- 760×900 深色识物。
- 分析结果。
- 减少动态与键盘焦点。

## 16. 前端变更评审清单

提交前逐项确认：

- [ ] 新界面是否减少了文字，而不是增加解释层级。
- [ ] 操作是否能通过位置、图形和状态自行说明。
- [ ] 是否引入了 emoji、中点、双语重复标题或编号步骤。
- [ ] 是否复用了现有令牌、图标和圆角。
- [ ] 关键动作是否在上下文中可见，点击后 100ms 内是否有反馈。
- [ ] 错误和超时是否能原位恢复。
- [ ] 600、760、1024 三档宽度是否无横向滚动。
- [ ] 鼠标、键盘、深色和减少动态模式是否都能完成任务。
- [ ] 是否保持现有后端契约和请求令牌行为。
- [ ] 单元测试、端到端测试、Rust 检查和 Tauri 构建是否通过。

这份清单用于保护 NativeLingo 的独特格调，也用于防止“看起来更丰富”重新替代“用起来更
直接”。
