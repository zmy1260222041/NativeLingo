# NPC 播放与录音操作冲突修复

用户反馈：NPC 语音尚未播放完时点击录音，会再次播放语音。

## 修复

- 到店开场配音与录音初始化会话原先分离，录音会调用 talk 并再次触发 service_entry。现在录音通过不播开场的会话初始化进入原有领域状态，不再用 talk 间接开始录音。其他主动交谈入口默认行为不变。
- 统一控制器的录音前置检查：实际播放器状态、播放 ID、待取台词/动态回复、队列、模型回应和录音请求。检查发生在任何取消活动或新建会话之前。
- UI 显示“对方正在说话”“正在准备语音”等状态并禁用录音按钮；每帧刷新轻量状态，语音结束即恢复。快捷键与已排队的 pressed 回调也受同一控制器检查约束。
- 玩家录音已开始时始终保留结束录音操作；可重试的失败恢复状态不会永久锁住录音。

## 验证

- NovelTest 通过：合成 PCM 实际播放期间连续触发鼠标 pressed 和 V 输入，原音频流与播放 ID 不变，不开麦、不重开招呼；播放结束信号后恢复按钮；动态回复等待时禁用。独立静音音频总线验证播放后首次点击开始录音，且没有重复 scenario_opened；结束录音按钮保持可用。
- NPC dialogue asset suite 通过；日志保留该套件原有 ObjectDB 退出泄漏警告。
- 真实本地 TTS + 非 headless Godot：五名角色均进入播放状态。在每条语音播放中连续触发三轮鼠标/快捷键请求，播放器时间继续前进、音频流未替换、没有再次播放事件、没有开始录音；5/5 通过。此项检验实际声音数据和播放器行为，不评价物理扬声器听感。
- 日志：novel_recording_conflict/。本轮没有提交或推送，保留前一轮启动修复。
