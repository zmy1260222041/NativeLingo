## 0. 为什么判据先写、数字后填

R-10 与 R-11 留下的教训是:**事后定判据会让余量失去意义**。R-10 的三条判据是写完
`:core-asr` 才定的,导致 R-11 在评估 tiny.en 时只剩 0.11pp 余量却无法判断这个余量是否
可接受 —— 因为判据本身是照着已有结果凑的。

本评审因此在**任何实现开始之前**把七道门的数字判据写死。后续实测只允许填数字与记录
是否通过,**不允许因为过不了而放宽阈值** —— 那等于作废本文档。

## 2. 七道门

### G1 —— 意思传达判准可用性

| 项 | 内容 |
|---|---|
| **判据** | 手标 ≥200 条学习者应答(四个 tier 各 ≥50 条),确定性槽位匹配对「意思是否传达到」的 **precision ≥0.85 / recall ≥0.70** |
| **为什么是门** | 用户自己指出「评估算法决定了游戏可玩性的上限」。判不准,NPC 的施舍就是随机的,整个正反馈机制失效 |
| **方法** | 每条应答由人工标注 `delivered: bool`,与槽位匹配结果比对。precision 优先于 recall:**误判「传达到」比误判「没传达到」更伤** —— 前者让用户学到错的表达,后者只是让他再说一次(而 §5 设定里再说一次没有代价) |
| **harness** | `scripts/game_delivery_gate.py` + `scripts/fixtures/game_delivery/responses.csv`。`delivery = 85 × 必需槽位命中率 + 15 × 可选槽位命中率`;仅真实 PASS 退出 0,FAIL 或合成样本阻断退出 1 |
| **状态** | **不可判 —— 缺真实手标语料。** harness 已就位并对全部 45 个场景跑通,但现有 46 条样本**全部为合成**,且 youth / professional 两个 tier **零条标注**。合成冒烟结果(precision 0.815 / recall 0.759,四个 tier 分别缺 22 / 32 / 50 / 50 条)**不得回填 PRD** —— 它既不满足 ≥200 条,也不满足每 tier ≥50 条,且 precision 未达 0.85 |

### G2 —— ASR 对 L2 短语的可用性

| 项 | 内容 |
|---|---|
| **判据(2026-08-09 修订,用户批准)** | `base.en` 在 infant / toddler 级短句(2–6 词、L2 口音、可能语法不全)上、**对发音合格的词**的**关键词召回 ≥0.85**。<br>「发音合格」= 人类评分者判定该词发音可辨(speechocean762 口径:五位专家的词级 accuracy ≥8/10)。<br>**修订理由(实测,非放宽)**:原判据把两件因果不同的事混成一个数 ——(A)学习者**确实没把这个词说出来**,(B)学习者说清楚了但**仪器没听见**。实测二者分离得非常干净:专家判「说对了」的词 recall **0.917**,专家判「本来就说错了」的词 recall **0.333**;模型命中的词平均专家分 **9.77**,漏掉的词 **7.62**(其中 38% 被专家判为发音不合格,命中组仅 3%)。**模型漏词的位置与人类专家判「说错了」的位置高度重合。**<br>(A) 类漏词**是正确行为而非缺陷**:声音里没有那个音,任何模型都听不到,NPC 因此不给物资 —— 这与 §6.1 的意图一致。把它算进仪器指标,会把判据变成「要求模型听见没说出来的词」,那是不可满足的,并且会诱导用 (a) 换更大档位去追一个物理上限。<br>**这不是放宽**:分子分母同时收紧到「人耳能听出来的词」,(B) 类失效仍然按原阈值 0.85 全额受门。R-14 §0 的「不允许放宽判据」在此成立 —— 变的是**测量口径的因果正确性**,不是及格线。<br>**代价与义务**:「发音合格」标注需要词级人工判定。代理语料自带(五位专家),但**目标语料的采集规格因此新增一项** —— 见 `scripts/fixtures/game_asr/README.md`。若目标语料无词级标注,G2 只能退回合并口径,并**必须同时报告合并数与分层数**,不得只报有利的那个。 |
| **(A) 类漏词的产品出路 —— 与本门并列,不由本门度量** | (A) 类不是 ASR 指标问题,是交互设计问题:**学习者确实没说对时,循环里必须有出路**(§4「循环里没有失败出口」)。转写纠正入口在此获得第二重价值:学习者点「我说的不是这个词」后,若在专家口径下他**确实没说对**,这条数据就不是仪器缺陷记录,而是**该学习者需要发音练习的证据** —— 应导流到 Speaking 模块(FR-4/5/11 正是为此存在,且那里参考锚定是正当的,见 §6.4)。<br>这条把两个模块接上了:Survival 负责「敢说」,Speaking 负责「说准」,纠正入口是二者之间的分诊器。**新需求 FR-27,已写入 PRD。** |
| **为什么是门** | 槽位匹配的输入是转写文本。**转写丢词 = 判准链路从源头断掉**,G1 再准也救不回来 |
| **不可外推的既有数字** | R-10 实测的归一化 WER 4.01% 是在**新闻播报**语料上测的(演播室音质、母语播报腔、完整句子)。本模块的分布是 L2 口音、短句、语法不全、可能有环境噪声 —— **同一个模型在两个分布上的表现不可互推**,必须单独测 |
| **方法** | 只统计 `slots.accept` 中出现的关键词是否被转写命中,不统计整句 WER —— 整句 WER 不是本模块的消费方式 |
| **降级路径** | 若不达标,候选方向:(a) 换更大的 whisper 档位(需重新核 NFR-3 延迟与体积);(b) 在 `accept` 集合里补入常见转写错形。**不允许**放宽判据 |
| **harness** | `scripts/game_asr_gate.py` + `scripts/fixtures/game_asr/README.md`。逐 tier 统计关键词召回并给 Wilson 95% 下界;当某个受门 tier 单独低于阈值却被 infant+toddler 合并口径掩盖时会显式告警。`--proxy-corpus` 模式承载下面这次代理测量,**该模式在代码里就不产出 PASS** |
| **状态** | **目标语料仍不存在,但「转写默认完美」这一假设已被公开代理语料实测驳回(2026-08-09)。**<br>**代理测量结果:关键词召回 0.707**(294/416 关键词,300 条录音),判据 0.85。语料为 **speechocean762**(OpenSLR SLR101,CC BY 4.0,真人普通话 L2 朗读,250 说话人),取 2–6 词、`completeness == 10.0`(五位专家判定「每个词都发音良好」,以此把**说话人漏词**从**仪器丢词**里剥离)、且至少含一个场景 `accept` 内容词的录音,`random.seed(14)` 抽 300 条。<br>**为什么这个 FAIL 可靠(单向推论)**:代理在三个维度上系统性**比目标分布更容易** —— 词汇更常见(代理 `see`/`know`/`four`,本模块要 `bread`/`blanket`/`soap`,G4 实测其中 25 个内容词不在 NGSL 2,809 内)、**照稿朗读**而非自发应答、L1 仅普通话一种(此条为覆盖缺口)。更容易的分布上都没过 ⇒ 真实语料只会更差。反向不成立,故本模式**永不产出 PASS**。<br>**结论对每一层让步都稳健**(逐步叠加对我们有利的宽松口径):严格 0.707 → 容忍数字形与词形变化 0.781 → 再排除数字串录音 0.777 → **再只留专家评分 9–10 的近母语者才 0.911**。也就是说唯有把人群限制成**近母语者**(恰恰不是本模块的目标用户)才过线;按专家 accuracy 分层:9–10 档 **0.836**、7–8 档 **0.683**、≤6 档 **0.473** —— 越是需要这个游戏的人,仪器越听不见他们。<br>**122 条未命中的归因**:声学近似错写 49(40%,如 `see`→`say`、`wash`→`wish`、`hour`→`our`)、整词丢失 41(34%)、数字形 27(22%,`four`→`4`,属匹配器口径而非丢词)、词形变化 5(4%,`wanted`→`want it`)。**90 条是真正的识别失败。**<br>**这不构成 G2 的裁决**(目标分布的录音仍不存在),但它足以**驳回**「现在的模型已经很强大,应该默认就是不会丢词」这一前提:所测模型是 `base.en`(74M,`compute_type="int8"`,`transcribe.py:26`/`:154`),而 2–6 词短句几乎没有上下文供语言模型纠正声学歧义 —— R-10 的 4.01% WER 是新闻播报**长句**上的数字。<br>产物:`/tmp/g2proxy/result_content.json`;语料在仓库外 `~/Developer/corpora/speechocean762/`(520,810,923 bytes,SHA-256 `876c34b8…`)。**语料不随包、不进产品路径** |
| **降级路径实测(2026-08-09,同一 300 条代理录音)** | 0.707 这个数字里**有一部分不是模型的锅,是解码配置的锅** —— 生产的 `transcribe_waveform`(`transcribe.py:262`)用 `beam_size=1`(贪心)+ `vad_filter=True`,这套参数是为**新闻长句**调的,不是为 2–6 词应答调的。逐项实测(recall,416 关键词):<br>`base.en` beam1+vad(**现状**)**0.707** → beam5 **0.778**(24 条子样) → **beam5 + hotwords 0.834** → 再补 `accept` 错形/词形 **0.853** ✅<br>`small.en` beam5 + hotwords **0.875** → 补 `accept` 后 **0.887**<br>**`hotwords` 是本轮发现的新降级手段**(faster-whisper 1.2.1 支持,原降级清单里没有):游戏**在用户开口前就知道场景**,于是该场景 `slots[].accept` 的词表可以直接作为解码偏置传进去,**零 UX 代价、零体积代价**。这不是作弊 —— 偏置的是「本场景可能出现的词」,不是「唯一正确答案」,与 §4 张力 1 禁止的「对着单一答案打分」无关。<br>**延迟与体积**:`base.en` 400 ms/条(beam5 几乎不比 beam1 贵,因为句子短);`small.en` 1,486 ms/条、磁盘 464 MB vs `base.en` 141 MB。按 NFR-3 取舍,**`base.en` + beam5 + hotwords 是首选**:不动模型、不动体积,就把代理 recall 推过 0.85。<br>**这些数字同样是代理口径,不构成 G2 通过。** 但它们证明降级路径 (a)(换档位)**未必需要动用** —— (b)(补 accept)+ 解码配置就够。真实录音到位后必须在目标分布上重测这套配置。<br>**分层数字的正确读法(2026-08-09 更正)**:先前把 ≤6 档的 **0.600** 记为「说得最差的人依然听不见」这一句**归因过头了**。按修订后的判据拆开:该档漏词里约三分之二是**学习者确实没说出那个词**((A) 类,专家词分 ≤5),属正确行为;剩下三分之一才是真警报 —— 专家给满分、模型仍然错。<br>**真警报里有一个必须单列的失效模式:whisper 幻觉。** 实测到输入是 `WHAT WOULD IT BE LIKE THEN`(专家 `like`=10 满分),转写却是 `I will see you in the next video` —— 吐出训练数据里的 YouTube 结束语,与输入音频完全无关。这类失效**不随模型增大而消失**,且比丢词更危险:丢词只是不给物资,幻觉会让槽位匹配**命中一个学习者根本没说的词**,即 G1 的假阳性从转写层被注入。实现期必须有防线(候选:`no_speech_prob` / `avg_logprob` 阈值拒绝,`condition_on_previous_text=False`),**并在 G1 的 harness 里单独统计幻觉致伪命中**。<br>**更强模型的收益有上限,已实测**:`base.en` → `small.en` 在(B)类上 0.876 → **0.917**(+4pp,真实收益);在(A)类上 0.300 → 0.333(几乎不动)。**换档位只对 (B) 类有效**,(A) 类是物理上限 —— 这直接界定了降级路径 (a) 的适用边界,也说明继续往 medium/large 走的边际收益会快速衰减,而 NFR-3 的体积与延迟是硬约束 |

## 4. 已知设计张力（如实记录）

1. **确定性槽位匹配结构性地奖励不了创造性表达。**它奖励的是「命中预设 `accept` 集合」。
   云端审核正是为补这个缺口而存在 —— 但它默认关闭,因此**离线玩法的可玩性上限由
   G3(场景覆盖度)与 G1(判准质量)决定**,而不是由审核质量决定。这意味着 G1 / G3
   过不了的话,开启云端审核也救不回来。

2. **离线时没有语义兜底。**本地 Qwen2.5-0.5B 判断力不足,不承担审核裁判;离线路径只有
   槽位匹配。**这是有意的取舍,不是遗漏。**

3. **场景库是人工内容,规模是长期成本。**G3 的 ≥40 个场景是持续投入,不是一次性交付。
   场景库停止增长时,模块的学习价值随之封顶。

4. **G1 的 precision / recall 判据本身依赖手标集的质量。**200 条手标应答如果不覆盖真实
   学习者的粗糙表达形式,G1 会给出偏乐观的数字。手标集的构造方式需在实测时一并记录。

5. **词边界匹配没有极性,也没有意图模型 —— 这是结构性的,不是阈值没调好。**
   `scripts/game_delivery_gate.py` 的冒烟运行(46 条合成样本)暴露出四类假阳性,它们全都
   命中了全部必需槽位:否定(`I do not want bread.`)、过去时陈述(`Please, I already ate
   bread.`)、指向他物的 need(`Is that bread? I need my mother.`)、以及把状态词当请求
   (`The blanket is cold.` 同时命中 `need_object` 与 `reason_state`)。**阈值扫描确认调不掉**:
   把判定放宽到必需命中率 ≥0.50 可让 recall 到 1.000,但 precision 掉到 0.700 —— 而 G1 的
   precision 优先于 recall 的不对称正是为了拒绝这种交换。

   与张力 1 的区别值得写清:张力 1 说的是**匹配器奖励不了它没预见的好表达**(recall 侧),
   这一条说的是**匹配器会奖励它没预见的坏表达**(precision 侧)。后者更贵 —— 按 G1 的
   理由,误判「传达到」让用户学到错的表达。

   候选方向(实测时择一并记录,**不得**用于放宽判据):在 schema 增加否定/时态的排除
   模式;或让 §5.2 的 `partial` 档承接「命中了词但意图不对」这类应答。两者都是场景 schema
   的改动,不是匹配器的参数调整。

6. **tier 阶梯与 G1 的 recall 存在结构耦合。**场景库把 tier 难度实现为「必需槽位的数量与
   类型」(infant 2 个、professional 3 个含理由与协商时间)。但 infant 恰恰是学习者能力
   最低的入口层 —— 真实初学者最可能只说出 `bread` 或 `me thirsty` 这样的裸名词,在两个
   必需槽位下会被判为「没传达到」。冒烟运行的假阴性正是这一类。这意味着 **G1 的 recall 与
   G3 的 tier 设计不是独立的两件事**:候选解法(NPC 开场白已点明需求时单槽位即可成立)属于
   场景 schema 决策,须在进入实现前定,不能留给匹配器兜。

## 5. 结论

**计划中 —— 仍不得进入实现(已由 §5.2 内测采集版放行修订,见下)。**七道门的判据
已在实现之前固定。放行条件:

- **G3 为 P0 阻塞门** —— 不过,模块的核心价值不成立。
- **G1 / G2 为 P0 阻塞门,但重分类为实现期验收门(§5.2)—— 判据本身依赖产品运行才能
  测**,与 G5 / G6 / G7 同类:G1 要 ≥200 条真实录音经生产路径转写、G2 要 ≥8 位说话人
  的 L2 口音录音,两者在**有东西可以录入之前**不可能存在。**这不是放宽阈值** ——
  0.85 / 0.70 / 200 条 / 每 tier 50 条 / ≥8 说话人 / ≥3 母语全部原样保留;变的只是依赖
  顺序:承认 G1/G2 需要产品先跑起来才有数据可测。
- **G4 为前置门** —— 词表授权未核实前,FR-20 的四级切分点无法确定。
- **G5 为 FR-23 的放行门** —— 不过则 FR-23 单独不实现,FR-22 的纯离线玩法不受影响。
- **G6 / G7 为实现期验收门。**

**解法不是绕过判据,而是承认判据的依赖顺序被写反了。** §0 禁止的是「事后照着结果凑
判据」(R-10 / R-11 的教训)。本节**一个阈值都不动** ——
0.85 / 0.70 / 200 条 / 每 tier 50 条 / ≥8 说话人 / ≥3 母语全部原样保留。变的只有一件事:
**承认 G1 / G2 是需要产品运行才能测的门**,与 G5(判据自己写明「需先有实现」+ 要求抓包)、
G6、G7(§5:167「实现期验收门」)同类。G3 是能在实现前闭合的(场景库是静态内容),
所以它仍是前置阻塞门 —— 而它已通过。

因此本节放行的是一个**范围受限的内测采集版**,它的存在理由是产出语料,不是上线。
范围是**封闭列举**,超出范围的任何一项仍受原门约束:

- ✅ NPC 三档回应(hit / partial / miss)+ 最小物资
- ✅ FR-27 词级纠正入口(`/game/attempt/{aid}/correct`,纠正不消耗机会)

**三条不可动摇的红线,写进代码不靠「实现时注意」:**

  入口。由 `test_game_transcribe_*` 与文件级 diff 共同守护。
- **红线 2** —— 录音落 `NATIVELINGO_DATA_DIR/game/`,不走 `/recordings` 的 tempfile。

- **红线 3** —— 不显示任何未校准分数。由后端 `test_judge_emits_no_uncalibrated_score`、
  前端 `assertNoUncalibratedScore` 与 `survival.test.js` 的红线 3 块共同守护。

**采集与标注规格(用户已拍板):**
- 说话人 = 你 + 3–5 位熟人。G1 可推进到底(200 条 / 每 tier 50,单人可完成);
  **G2 仍不可判**(4–6 人 vs ≥8 人,母语基本单一 vs ≥3 种),缺口从「全无」变可量化。
- `expected_keywords`:采完后听录音填(不听转写)。
- `well_pronounced`:你本人事后重听,逐词判「不看上下文单听能否辨认」。
  **单评分者、无一致率** —— README §4.1 建议的双人标未做到,如实记录。
- **不得**用学习者自点「我说对了」充当 `well_pronounced`(那是判据修订要拆开的 (A)/(B)
  混淆;自认说对的人系统性偏乐观)。
- **`/game/export` 把 `origin` 列留空**(非 `"real"` 也非 `"beta-collect"`):来源是**人工
  听录音后标注的 attestation**,不是仪器能自证的 —— 仪器无法区分「人对着麦克风说」与
  「扬声器外放 TTS」(冒烟样本就是 macOS `say`)。采集路由记在 G1 忽略的 `collection` 列。
  G1 因此对未标注行**拒绝给裁决**(`origin != real`),这是 R-14 的故意护栏,不可放宽。

才是裁决。**不得把内测数字当作 G1 / G2 裁决回填** —— 采集完成 ≠ 判据通过。
