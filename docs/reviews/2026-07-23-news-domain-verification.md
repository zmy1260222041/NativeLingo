# 新闻域验证报告(FR-M2 素材库铺路)

> 日期:2026-07-23 · 依据:PRD §7 附录(FR-M1 真实新闻素材的 4 项待验证技术点)
> 素材:7.1.mp4(CBS News Special Report,636s,真实新闻播报)
> 结论:**4 项全部通过,FR-M2(应用内素材库)在技术侧解锁**;长句二级切分已实现(CACHE_VERSION 4);新发现 1 项长选段 MPS 内存风险(见 §5)。

---

## 1. whisper 转写质量(base.en 是否够用)✅ 通过

- **模型置信度**:258 段,avg_logprob 均值 −0.160(p10 −0.24),**零**低置信段(< −0.7);no_speech_prob ≈ 0.02。
- **跨模型一致性**(base.en vs small.en,1943 词):**98.3% 文本一致**。33 处差异集中在专有名词(主播姓名)、虚词遗漏、数字格式(seven two / 7 2),不影响跟读评分(词边界来自 MMS,逐词评分以参考文本为锚)。
- **结论:base.en 对新闻播报域够用**,无需为 FR-M2 升级;专有名词密集素材可选 small.en(每视频一次性成本)。

## 2. MMS 强制对齐鲁棒性 ✅ 通过

- 1944 词:词时长中位 0.200s(p1 0.040 / p99 0.760);塌缩 <50ms 共 61 词(3.1%),**全部为 "a"/"I"/".S." 等真实短功能词**,非对齐失败;超长 >1.5s 为 0;重叠 <−50ms 仅 7 词(0.36%);零/负时长 1 词。
- 一致性抽查(6 句重对齐):边界差中位 **10ms**(p90 18ms),None span 为 0。
- **结论:对背景音乐/播报语速鲁棒**,fallback 路径未被触发。

## 3. 长句跟读粒度 ✅ 已实现二级切分(FR-M3)

- **问题确认**:43% 句子 >6s 或 >18 词(最长 22s/64 词),不适合整句跟读。
- **实现**(`transcribe.py`,CACHE_VERSION 3→4):超长句(>8s 或 >20 词)在从句边界递归二分——优先逗号/分号/冒号,其次连词(and/but/because/which/that...),取离中点最近且两侧 ≥4 词的切点。
- **效果**:105 → 164 句;中位 4.12s→3.50s,p90 11.34s→6.24s,最长 22s→7.66s;残余 >8s/>20词 仅 3 句。切点落在自然从句边界(人工抽查确认)。

## 4. 端到端评分抽查(NFR-Q1 复验)✅ 通过

- 真实 CBS 原声(12.9s,3 句)+ 异嗓音学习者(Daniel @150wpm):**accuracy 89.1 / fluency 88.1**,rate 1.085;全部词 good、零误报、零误判 tip;MMS 学习者回放区间正常。
- 与 R-1 评审结论一致:TTS 校准在真人参考下行为正常。

## 5. 新发现问题(已记入 open-issues)

- ⚠️ **长选段 MPS OOM**:wav2vec2 编码 ~7 分钟连续选段时注意力分配 8.65GiB 触发 MPS 内存上限。产品语境下用户选段通常 ≤ 数句,但应选择长选段时应在前端限制或后端分块编码(30s 滑窗)。优先级 P2。

## 6. 对 FR-M2 的结论

新闻域技术链(转写 → 对齐 → 切分 → 评分 → 回放边界)在真实播报素材上全部验证通过。**FR-M2(应用内素材库)可以启动**,剩余为产品/工程工作(素材元信息、导入流程、版权合规形态),无阻塞性技术风险。
