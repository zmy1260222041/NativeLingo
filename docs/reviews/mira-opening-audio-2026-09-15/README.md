# Mira 开场文字与语音同步

用户路径：点击「从头开始」，关闭引导，Mira 的开头几句英语已经显示，但还没有声音。

原因：控制器在 `dialogue_ready`（模型文字就绪）时立即显示英文，界面开始打字；音频仍需等待 TTS 和传输完成。实际服务测试中，文字在 994 ms 到达，音频在 5503 ms 开始，原来会提前约 4.5 秒显示英文。

修复：控制器暂存动态回复，在对应 NPC、回复 ID 的 `line_audio_ready`（播放器已经调用 play）到达时才显示英文并开始打字。关闭引导后立即显示「正在准备开场语音…」，不继续展示旧的静默问候。取消时清除待播文字；语音失败时保留可读文字并提示重试。服务本身的文字生成信号和对话结算时机不变。

验证使用 `build/art-playtest` 的独立应用目录，禁用进度持久化，不读取用户存档、不使用麦克风：

- `NovelReplyAudioTest`：10 项通过，覆盖延迟、其他 NPC/旧回复回调、重复事件、音频先于文字、取消、失败降级、生成失败退出等待提示。
- `LiveMiraOpeningTest`：真实模型/TTS、真实 AudioStreamPlayer，完整执行两次从头开始与关闭引导。两次文字显示与音频开始分别均为 5503 ms、4103 ms；音频含非零样本、完整播完、播放后录音解除锁定。详见 `live.log`。这是应用播放状态与音频数据验证，不是人工听音或物理麦克风测试。
- `NovelTest`：通过，包括启动、取消、物品、存档和三夜流程。
- `TownBelongingTest`：9 项通过，未播放/取消回复不计入关系熟悉度。
- `CampusInteractionTest`：26 项通过；`NovelInteractionTest`：通过。后者及新增界面测试退出时仍有 ObjectDB 实例泄漏警告，未在本次修改中处理。
