# 音素级诊断(MDD)符合性评审:假设打分式方案 vs FR-11「宁缺毋滥」

> 日期:2026-07-23 · 评审依据:`docs/PRD.md` FR-11(音素级替换诊断;**宁缺毋滥,不确定时静默**)
> 实现:`backend/core/phoneme.py`(v1.4),集成于 `pipeline.analyze_detailed`
> 结论:**符合 FR-11 的「宁缺毋滥」约束**——三重独立门控(仅对 weak/bad 词 + canonical 自验证门控 + 替换增益 margin)使正样本精准命中、负样本与坏解码一律静默;召回受参考解码质量上限约束(已知且接受的取舍)。

---

## 1. FR-11 要求与方法回顾

**FR-11(P2)验收**:能给出"/θ/ 读成了 /s/"级替换诊断;**不确定时静默**(精度优先于召回)。

**方案**(详见 CHANGELOG v1.4,此处只列与符合性相关的要点):

- **不解码学习者**:wav2vec2 CTC 对 ~0.3s 孤立词贪婪解码噪声过大(实测 θ/s/ʃ 起音频繁丢失,补零上下文属分布外反而更差)。改为**只解码参考音**得 canonical IPA(原声清晰,且天然携带主播本人读音,贴合跟读场景)。
- **假设打分**:把 canonical 经 CTC Viterbi 强制对齐到**学习者**的 emission,得每帧均对数概率 `base`;再枚举每个音素位的单音素替换/删除变体,取增益最大的 `gain = score(变体) − base`。
- **接受条件**:`gain > _MARGIN`(0.15/帧)才采信一个替换。

关键设计点:**MDD 只在已标 weak/bad 的词上触发**,且**额外要求 canonical 能拟合参考音自身**——这两点是「宁缺毋滥」的工程兜底,见 §2。

## 2. 三重门控 → 精度优先

诊断要真正输出,必须同时穿过三道独立闸门:

| 门控 | 位置 | 作用 |
|---|---|---|
| ① 词级预筛 | `pipeline.py`:`w.status in ("weak","bad")` | 只对校准 DTW 路径已判弱/错的词尝试诊断;good 词永不触发 |
| ② canonical 自验证门控 | `_GATE_MAX=0.05`:同一替换扫描**先在参考音自身 emission 上跑** | 若 canonical 连参考音都拟合不过(gate gain > 0.05),说明解码本身坏了 → **该词静默** |
| ③ 替换增益 margin | `_MARGIN=0.15`:学习者侧增益须超阈 | 增益不足 = 证据是解码噪声 → 不出诊断 |

三闸串联:任一不过即静默。这是召回低、精度高的**结构性保证**,而非调参碰运气。

## 3. 实测证据(`scripts/mdd_margin_sweep.py`,`say` 合成最小对)

### 3.1 负样本(同一音频;须静默)✅ 干净

| 词 | canonical | 最优变体增益 |
|---|---|---|
| think | /θɪŋ/ | **−0.026** |
| sheep | /siː/ | +0.036 |
| bad | /bad/ | −0.009 |
| very | /vɛɹi/ | −0.158 |
| well | /wɛl/ | −0.016 |

全部 ≤ +0.036,**远低于 margin 0.15 与 gate 0.05**。同一音频不产生任何幻诊——`test_same_word_no_phantom_diagnosis` 覆盖。

### 3.2 正样本(canonical 可信时;须命中)✅ think→sink

`think`(/θɪŋ/)→ `sink`:最优变体增益 **+0.332**(≫ margin),且**精确定位在 /θ/**。`test_theta_dropped_in_sink_is_flagged` 断言 tip 含 "θ",通过。

### 3.3 坏 canonical(参考解码失败;须静默)✅ 门控生效

`say` 合成的 thin/ship/fan/light 等,参考 CTC 解码退化为垃圾 IPA(`iɛ5n`/`s.i.5`/`siɛ5n`/`laɪd`)。在**裸 sweep**(不挂门控)下它们仍会报出高增益伪诊断(fan +0.365);但生产路径的门控 ② 会在参考音自身检测到 canonical 不合身(gate gain > 0.05)而**静默**。`test_broken_canonical_stays_silent`(fan→van)验证此行为:不崩溃,且不出错误诊断。

> 这正是门控 ② 的价值:它把「解码坏了」与「真有替换」区分开,使 MDD 不会在解码噪声上自信地报错。

### 3.4 全量回归

`pytest backend/tests/` **12/12 通过**(phoneme 3 + recordings 2 + pipeline 2 + track_b 5);`pipeline.analyze_detailed` 集成处 try/except 兜底,音素轨永不中断主分析。

## 4. 召回上限与已知取舍(不阻塞,记录备查)

符合「宁缺毋滥」的代价是召回受限,以下为已知且接受的取舍:

1. **参考解码质量是上限**。对 `say` 合成的个别词(thin/fan/ship/light)canonical 解码失败 → 门控静默(漏诊)。**对真人原声预期更好**(更自然的连续语音语境,正是 CTC 音素模型的训练分布);待真实素材上抽查确认。
2. **近亲音对区分力弱**。ɪ/iː、æ/ɛ 等最小对增益常 < margin → 静默。单编辑假设打分对声学相近的替换本就区分力有限;精度优先于召回的设计取舍。
3. **归因 kind 偶有偏差,定位不偏**。think→sink 的最优变体是 **delete θ**(gain +0.332)而非 substitute θ→s:单编辑打分有时偏好"删掉该位、让 blank 吸收"的路径,胜过"替换为 /s/"。后果:verbalizer 对 delete 会说"/θ/ 被吞掉了",对 think→sink(实为 θ→s)措辞略偏;但**问题音定位在 /θ/ 是正确的**,满足 FR-11"指出哪个音"的核心诉求。如未来需精确区分删/换,可引入双编辑假设或对 canonical–learner 做 IPA 序列对齐(本项目 `diff_phonemes` 已具备该能力,当前生产路径未启用)。

## 5. 对 FR-11 的结论

**符合 FR-11**。「/θ/ 读成了 /s/」级的替换诊断在 canonical 可信时**精准命中**(think→sink 增益 +0.332,定位 θ);「宁缺毋滥」由三重门控**结构性保证**——负样本增益 ≤ +0.036、坏 canonical 被自验证门控静默、good 词永不触发。召回上限(参考解码质量、近亲音对、归因 kind)属已知取舍,不违反 FR-11 的精度优先验收标准。

**后续可选项(未排期)**:在真实新闻素材上抽查正样本命中率(预期优于 `say` 合成);若需精确删/换归因,启用 IPA 序列对齐路径。
