# 物品交互 UX — FR-44

- 状态：已批准，可玩基线；视觉精修于 2026-09-07 复核
- 平台：桌面键鼠、手柄、桌面/网页无语音构建
- 规则来源：`../gdd/item-usage.md`
- 视觉来源：`../art/art-bible.md` §6、`../art/item-usage-assets.md`

## 1. 目的与玩家需要

本界面让玩家看见、选择并使用自己通过交流获得、能够自主支配的生存物资。它不承担词汇观察、练习或
`heard → spoken → used` 增益；词汇系统仍在其异步流程中独立结算。

玩家需要始终分清三件事：物品现在在哪里、下一步能做什么、动作是否已经产生效果。食物与饮品可以在柜台
现场使用或打包；日常用品只能带回住处，在兼容位置先放置、再使用。

## 2. 入口、退出与导航

- 柜台成交后显示有名称的实物。靠近实物并交互，打开该柜台的待领清单。
- 按住 `Tab` / `RB` 打开随身物品，松开关闭；暂停菜单可改为切换模式。
- 方向键 / 十字键上下选择，`E` / `X` 执行主动作，`R` / 十字键右执行次动作，`T` / 十字键左全部打包。
- `Esc` / `B` 或右上关闭按钮退出。打开后焦点进入第一件物品；空列表时进入关闭按钮。
- `Tab`、`Shift+Tab` 与四向焦点形成面板内部闭环，不落到被遮挡的 HUD。
- 左肩键 `LB` 保留录音，右肩键 `RB` 才是物品条，不互相占用。
- 按钮均来自 InputMap、显示当前映射并可鼠标点击；物品界面未打开时不截获物品动作键。

## 3. 信息架构与组件

| 顺序 | 组件 | 内容与行为 | 数据来源 |
|---:|---|---|---|
| 1 | 标题栏 | 场景名、用途副标题、关闭按钮 | 打开模式 / 住所槽定义 |
| 2 | 携带容量 | 吃喝 `已用/4`、住所用品 `已用/1` | `ItemState.used_slots` |
| 3 | 织带分隔 | 苔薄荷短带 + 暮蓝尾带，只作层级锚点 | 视觉常量 |
| 4 | 物品列表 | 类别图形、具体名称、位置状态、剩余次数 | 稳定物品实例 |
| 5 | 详情卡 | 当前物品的下一步、适用住所位置或实际恢复效果 | `ItemCatalog` 定义 |
| 6 | 状态反馈 | 浪费确认、容量不足、安全条件、完成等短文本 | `item_command` 结果 |
| 7 | 动作区 | 主动作、可选次动作、柜台全部打包 | 当前实例状态与位置 |

列表每份独立，不把两个实例合并成一个不可追踪的总数。条目使用三种灰阶也可区分的轮廓：开口食物种荚、
瓶形饮品、承托式住所槽；类别色只作冗余。选中态同时使用左侧实体色带、底色变化与焦点描边。

## 4. 情境动作

- 柜台食物/饮品：主动作“现场吃/喝一份”，次动作“打包带走”；多份时出现“全部打包带走”。
- 随身食物/饮品：主动作吃喝；显示非零恢复项与剩余次数。
- 柜台日用品：只能打包，不显示现场使用的假动作。
- 住所领取箱：取出一件到随身。
- 床铺 / 维修位 / 电力位：携带兼容用品时主动作放置；已放置时主动作铺好/安装/使用，次动作收回。
- 生效耐用品：主动作可停用并留在原位；不可收回状态不显示误导按钮。
- 部分效果会溢出时第一次动作仅显示确认；第二次对同一实例执行才消耗。取消、切换条目或系统事件清除确认。

## 5. 状态矩阵

| 状态 | 列表 | 详情 | 动作 | 恢复 |
|---|---|---|---|---|
| 正常 | 当前实例 | 状态 + 下一步/效果 | 按情境启用 | 即时 |
| 空 | “与店员交流获取可支配物资” | 隐藏 | 主动作禁用，仅可关闭 | 交流或离开 |
| 容量不足 | 保持原实例 | 保持 | 不自动丢弃 | 逐份处理或回住所存放 |
| 不安全 | 保持原实例 | 保持 | 返回可读原因 | 落地、停步、结束对话 |
| 浪费确认 | 当前实例仍选中 | 保持 | 同动作再次确认 | 再按一次或取消 |
| 状态已变化 | 刷新后重新选择 | 最新值 | 拒绝旧 revision | 重新执行 |
| 高优先级打断 | 关闭 | — | — | 事件结束后重新打开 |

网络加载和服务错误不属于物品面板：物品只在已验证成交后出现，面板读取本地权威账本，不显示虚假的加载态。

## 6. 中断与安全

暂停、日切、昏倒、录音、正在进行的服务会话会关闭物品界面。世界移动不停时，面板只拦截自己的动作键；
跳跃、奔跑、转身未完成或离地时拒绝使用。离开柜台/住所交互距离会关闭情境面板，不能远程领取或放置。
邻近 NPC 本身不等同已在服务会话，不阻挡领取。

## 7. 视觉与响应式规则

- 外层必须使用项目 `SiltInkPanel`：深色半透明底、淤泥墨手绘轮廓、右上折片切角；禁止四角同圆的平板卡片。
- 主标题 28 px，正文 18–20 px，容量/状态 16–17 px；继承 Noto Sans SC 与 HUD 100–150% 缩放。
- 面板宽度不超过视口 90%，高度不超过 75%；1152×648 / 150% 时最多显示三行并滚动。
- 列表条目最低 52 px；所有动作与关闭按钮保持至少 44×44 px 可点击区域。
- 少量物品时按实际内容收紧面板，不保留大块无意义滚动空白；多项时只滚动列表，标题、详情与动作固定。
- 选中/焦点的 3 px 描边不只依赖颜色；主动作比次动作更亮，但两者文字对比度一致。
- 减少动态时使用静态状态切换。若后续加入展开动效，标准为 170–200 ms cubic-out；减少动态时为 0 ms。
- 音频关闭时所有结果仍有可见反馈。当前实现不以声音作为完成确认的唯一信号。

中文标题目标不超过 10 个全角字，动作不超过 12 个全角字；英文标题目标不超过 24 字符，动作目标不超过
30 字符。超出时按钮使用省略提示并保留 tooltip，正文允许智能换行。

## 8. 事件与数据责任

| 事件 | 触发点 | 最小属性 | 责任方 |
|---|---|---|---|
| `item_panel_opened` | 面板成功打开 | mode, location | UI（若接分析层） |
| `item_selected` | 当前实例变化 | item_id, state | UI（若接分析层） |
| `item_command_resolved` | 权威命令返回 | command, ok, reason | GameState / ItemState |
| `item_panel_closed` | 主动或系统关闭 | reason | UI（若接分析层） |

事件名称是稳定分析合同建议；当前版本不为埋点引入新的外发数据。物品实例、transaction id、revision 与效果
始终由 `GameState.items` 权威拥有，UI 不复制可写状态。

## 9. 验收标准

- [x] 柜台、随身、住所三种入口显示不同标题与下一步。
- [x] 食物/饮品与日用品不会出现彼此的错误动作。
- [x] 外层为 SiltInk 折角框；列表有非颜色类别图形与明确选中标记。
- [x] 打开/刷新/空列表都把焦点留在面板内部，键盘与手柄形成闭环。
- [x] 1152×648 / 150% 下外框、标题、容量、滚动区、详情和主动作均在视口与面板内。
- [x] 浪费、容量不足、不安全、错误位置与成功都有可见短文本，且失败不消耗物品。
- [x] 暂停、日切、昏倒、录音、服务会话和离开范围按规则关闭。
- [x] 物品动作不产生任何词汇库状态或增益。
